# Blind Whisper

> **Documentation rule:** `docs/` holds the living technical documentation
> (index: `docs/README.md`). Every implementation batch that changes behavior —
> a table, endpoint, scheduler, env var, or user-facing feature — must update
> the relevant `docs/` page(s) in the same commit series.

An anonymous video recommendation platform — paste a video URL, add a mood tag and optional note, then send it to a known person via Whisper Link (guaranteed anonymous delivery) or post it to Circle for organic community discovery — without revealing your identity. (Ghost Boost, a third delivery method, is paused — see the delivery-methods bullet below.)

## Run & Operate

- `pnpm --filter @workspace/api-server run dev` — run the API server (port 8080)
- `pnpm --filter @workspace/blindwhisper run dev` — run the frontend (port 22964)
- `pnpm run typecheck` — full typecheck across all packages
- `pnpm run build` — typecheck + build all packages
- `pnpm --filter @workspace/api-spec run codegen` — regenerate API hooks and Zod schemas from the OpenAPI spec
- `pnpm --filter @workspace/db run push` — push DB schema changes (dev only)
- Required env: `DATABASE_URL` — Postgres connection string
- Required env: `CLERK_SECRET_KEY`, `VITE_CLERK_PUBLISHABLE_KEY` — Clerk auth. The api-server's clerkMiddleware falls back to `VITE_CLERK_PUBLISHABLE_KEY` when a plain `CLERK_PUBLISHABLE_KEY` (no `VITE_` prefix) isn't set, so one secret covers both frontend and backend — but if `CLERK_PUBLISHABLE_KEY` IS set, it takes priority, so keep it in sync with `VITE_CLERK_PUBLISHABLE_KEY` (same value) rather than leaving a stale one behind. A mismatch here silently authenticates against the wrong Clerk instance — every request looks unauthenticated (`x-clerk-auth-reason: session-token-iat-before-client-uat`) no matter how many times a user signs in, since it's a server misconfiguration, not a browser/session problem.
- Optional env: `SMTP_USER`, `SMTP_PASS` — Whisper Link email channel + reply notification emails, sent over SMTP through the Titan mailbox (host/port default to `smtp.titan.email:465`, overridable via `SMTP_HOST`/`SMTP_PORT`; `EMAIL_FROM` defaults to the SMTP user). Legacy fallback: `RESEND_API_KEY`. Skipped with a log warning if neither is set. Also `COMPANY_MAILING_ADDRESS` — physical postal address appended to every email's CAN-SPAM compliance footer
- Optional env: `TWILIO_ACCOUNT_SID`, `TWILIO_AUTH_TOKEN`, `TWILIO_FROM_NUMBER` — Whisper Link SMS channel (skipped with a log warning if unset)
- Optional env: `TWILIO_WHATSAPP_FROM`, `TWILIO_WHATSAPP_CONTENT_SID` — Whisper Link WhatsApp channel. Requires a Twilio-enabled WhatsApp sender AND a Meta-approved Content Template with a single `{{1}}` variable for the link (build it in the Twilio Console's Content Template Builder) — WhatsApp business-initiated messages can't use free-form text for a first contact. Skipped with a log warning if unset.
- Optional env: `FREE_PLAN_WHISPER_LINKS` — overrides the free plan's 3-Whisper-Links-per-month cap (a number, or `unlimited`). Useful while billing isn't built out; unset restores the default
- Optional env: `RECIPIENT_FREE_REPLIES` — how many times an **anonymous** recipient can reply to one whisp before the thread closes (default 3, or `unlimited`). Signing up removes the cap entirely; a sender can also add more via `whisps.reply_credits_purchased` (purchase flow not built yet)
- Optional env: `STRIPE_SECRET_KEY`, `STRIPE_WEBHOOK_SECRET` — Credits & Plan checkout (returns 503 if unset)
- Optional env: `PUBLIC_APP_URL` — overrides the auto-detected frontend origin used in shared links and Stripe redirect URLs; **required** (not just recommended) for Scheduled Sending, since the background dispatcher has no per-request Host header to derive it from — a scheduled whisp is left queued with a warning log if this is unset when it comes due
- Optional env: `VAPID_PUBLIC_KEY`, `VAPID_PRIVATE_KEY`, `VAPID_SUBJECT` (a `mailto:` address) — Web Push notifications to senders when their whisp is opened/watched/replied to. Generate a keypair with `pnpm dlx web-push generate-vapid-keys`. Skipped with a log warning if unset; `GET /api/user/push-public-key` returns 503 until configured.
- **Required to access the admin panel:** `ADMIN_EMAILS` — a comma-separated list of email addresses (e.g. `you@example.com,cofounder@example.com`) that get auto-promoted to the `admin` role the next time that account signs in or makes any API request. There's no other way to create the first admin (a UI for granting admin access would need an admin to already exist). Once promoted, `/admin` appears in the app's nav for that account.
- **Required for uploaded-video playback/storage:** enable **Object Storage** for this app in Replit's Tools panel (no API key needed — Replit binds a default bucket automatically and `@replit/object-storage` talks to it via Replit's local sidecar). Without it, `/api/media/upload` returns 503 and the rest of the app is unaffected.
- Optional env: `ANTHROPIC_API_KEY` — powers the AI takeaway feature (`lib/aiTakeaway.ts`). Without it, takeaways are simply never generated (skipped with a log warning) — no other feature is affected.
- `pnpm --filter @workspace/api-server run test` — run the API server's Vitest suite (needs a reachable `DATABASE_URL`)
- After pulling schema changes, run `pnpm --filter @workspace/db run push` again — this round added **`notifications.kind`** (so the Replies tab badge can count reply notifications specifically) and **`whisps.reply_credits_purchased`** (extra anonymous replies a sender can buy for one whisp), on top of the prior round's **`suggestion_agent_status` table** (a singleton row tracking the AI discovery agent's last run — see Architecture decisions below), on top of the prior round's `suggested_videos` table (Suggestions Library) and the earlier rounds' unique constraint on `match_subscribers.email` (a post-launch bug fix — see Architecture decisions below; if drizzle-kit reports any duplicate-email rows blocking the constraint, that means the same inbox subscribed under two different casings before this fix shipped — merge or delete the duplicate manually before re-running push), on top of the prior rounds' `videoEndSeconds` on `whisps` and the new `match_subscribers` table, `uploadedVideoId`/`aiTakeaway`/`aiTakeawayStatus`/`aiTakeawayGeneratedAt` on `whisps` and a new `uploaded_videos` table, `expiresAt`/`reminderCount`/`nextReminderAt`/`lastReminderAt` on `whisps`, `appreciationResponse`/`appreciationRespondedAt` on `whisps`, `whisper_groups`/`whisper_group_members` tables + `groupSendId`/`whisperGroupId` on `whisps`, `circles`/`circle_members`/`push_subscriptions` tables, `role`/`banned`/`country`/`region`/`city`/`lastSeenAt` on `users`, `videoTranscript` on `whisps`, and `whisp_categories`

## Architecture decisions

- Contract-first: all API changes go in `openapi.yaml` → `codegen` → generated hooks/zod schemas
- Dark mode only — no light mode variants needed
- Zod schemas in routes must import from `"zod"` not `"zod/v4"` (catalog pin is ^3.25.76)
- Public whisp pages (`/w/:token`) are unauthenticated; everything else requires Clerk
- Three delivery methods: `whisper_link` (requires a known recipient, status goes straight to `delivered` — this is the only method that guarantees delivery to one specific person), `ghost_boost` (credit-spend, no recipient collected at send time — queued `pending` and fanned out to opted-in subscribers by `lib/matching.ts`/`lib/matchScheduler.ts`, see below), `circle_drop` (no recipient, visible in the public `/api/public/circle` community feed, status `delivered`)
- Whisper Link has three channels (`whisperChannel` on the whisp: `email` | `sms` | `whatsapp`), chosen by the sender in the composer. Email uses Resend, SMS/WhatsApp use Twilio (`lib/sms.ts`) — all three are optional-config-gated the same way (log a warning and no-op if unset, the whisp still gets created).
- Shared links go through `/api/l/:token` (`routes/link.ts`), not straight to `/w/:token`. In production the frontend is served as static files with an SPA rewrite (`artifact.toml`: `/* → /index.html`), so it can never return different Open Graph tags per whisp to a link-preview crawler — `/api/l/:token` is a real server route that detects known crawler user agents (WhatsApp, iMessage-adjacent bots, Slack, Twitter, etc.) and serves a per-video OG card (title/thumbnail/hook line), then redirects everyone else straight to the real `/w/:token` SPA page.
- The recipient-facing hook line ("Someone who cares about you thought you needed to see this 👀") is defined once in `lib/copy.ts` (`HOOK_LINE`) and reused in the email, SMS, WhatsApp template variable, and OG description — keep `PublicWhispPage.tsx`'s lead text in sync by hand, since frontend and backend don't share a constants module.
- **Ghost Boost is deliberately not a real Meta/TikTok ad integration.** Those platforms enforce a minimum matched-audience size before a Custom Audience can be used for targeting, so there's no way to guarantee an ad reaches one specific identified person — and building a "target this one known person" ad system runs directly into their anti-harassment ad policies. Whisper Link is the mechanism that actually satisfies "reach a known person anonymously"; don't reintroduce Ghost Boost as a literal ad-placement feature without solving that mismatch first. Instead, reach comes from `lib/matching.ts`'s own opt-in subscriber queue — see the matching-queue bullet below.
- **Anonymous matching queue** (`lib/matching.ts`, `lib/matchScheduler.ts`, `routes/subscribe.ts`, `match_subscribers` table): anyone can opt in at `/subscribe` (no Blind Whisper account needed) with an email + up to 8 topics from the same 15-category taxonomy `lib/categorize.ts` tags whisps with, confirmed via a double opt-in verification email (`/verify-subscription?token=`) before they're match-eligible — this is a real mailing list, so a stranger can't sign someone else's address up to get spammed. `startMatchScheduler()` polls every 10 minutes for `ghost_boost` whisps still `pending` with no `groupSendId` (i.e. the campaign "container" row, not yet fanned out) and calls `matchGhostBoostWhisp()`, which fans out one whisp row per matched subscriber (same "shared `groupSendId` ties a fan-out back to one logical send" pattern Group Whisper uses) — category-overlap matched (Postgres `&&` on the subscriber's and whisp's category arrays, via a raw `sql` template since Drizzle has no array-overlap helper; falls back to a broad, any-category match after a `CATEGORIZATION_GRACE_MINUTES` (5) grace period if the whisp's own categorization hasn't landed yet, or came back only as the non-subscribable `"uncategorized"` fallback), respecting a `MATCH_COOLDOWN_HOURS` (48) per-subscriber cooldown so one eager subscriber's inbox doesn't get flooded, capped at `MAX_MATCHES_PER_SEND` (10) total reach over a `MATCHING_WINDOW_DAYS` (14) window, after which the campaign is marked terminal (`delivered` if it matched anyone, `failed` if it never did). **Anonymous both ways** — unlike Group Whisper's fan-out (fine to show the sender, since they picked those contacts themselves), a Ghost Boost fan-out row carries a *stranger's* email the sender was never meant to see: `excludeMatchDeliveries()` in `routes/whisps.ts` filters these rows out of every sender-facing whisp lookup (`GET /whisps`, `/whisps/stats`, `/whisps/:id`, `/:id/replies`, `POST /:id/replies`, `DELETE /:id`, `/:id/reveal` — a post-launch bug fix widened this from just the first three), and `routes/public.ts` skips the sender's push/email notifications entirely for individual open/watch/reply/appreciation events on a fan-out row (another post-launch fix — the notification payload's link was itself a way to reach one specific subscriber's data before this). The sender's only visibility is an aggregate-only `GET /whisps/:id/matches` (matched/opened/watched/replied/appreciated counts, never per-subscriber). A subscriber can unsubscribe with one click from any matched email (`/unsubscribe?token=`) — idempotent, no login, standard for email compliance. `email` on `match_subscribers` is unique and always stored lowercased+trimmed (another post-launch fix — two differently-cased rows for the same inbox could each independently pass matching.ts's per-campaign dedup and get matched, and emailed, twice); resubscribing an address that was previously unsubscribed doesn't clear `unsubscribedAt` until a fresh click on the (re-sent) verification link proves inbox access again — a bare `POST /subscribe` alone can no longer silently reactivate someone.
- Watch tracking: YouTube/Vimeo videos are embedded in the public whisp page (`videoEmbedUrl`, computed in `video.ts`'s `buildEmbedUrl`) and report real `watched_10s`/`watched_50pct`/`watched_complete` events via each platform's JS Player API (`VideoPlayer.tsx`). Every other platform (TikTok/Instagram/Facebook/etc.) has no embeddable player with progress events, so only `opened`/`clicked` are tracked and the recipient is redirected out.
- Stripe Checkout (redirect-based, no client-side Stripe.js) wired for credit packs (one-time) and plan upgrades (subscription); webhook at `/api/billing/webhook` grants credits/plan on `checkout.session.completed`, keyed by the Stripe checkout session id (`stripePaymentIntentId` on `credit_transactions`) so a retried webhook delivery can't double-credit
- Free plan is capped at 3 Whisper Links per rolling 30-day window (`lib/plans.ts`); Spark/Ember are unlimited
- Security posture (see `lib/rateLimit.ts`, `app.ts`, `routes/video.ts`): CORS only allows the app's own origin (same Host as the request, or an explicit `PUBLIC_APP_URL`/dev-port allowlist) — never reflects arbitrary origins, since Clerk auth is cookie-based. `/api/video/meta` only fetches URLs on an allowlisted set of video-platform hostnames (checked via `new URL().hostname`, not substring matching) to prevent SSRF against internal services. The unauthenticated public endpoints (`/api/public/*`, `/api/l/:token`) are rate-limited per IP since each triggers a real side effect (DB write, and for `/reply` an email to the sender) — `publicEndpointLimiter` is applied exactly once per request in `routes/index.ts`, as its own middleware layer ahead of the three routers mounted at `/public` (a post-launch bug fix: mounting the same limiter instance separately on each of those three `router.use("/public", limiter, ...)` calls re-ran it — and re-incremented its counter — for every router a request fell through without a route match before finally hitting the one that handled it, silently cutting the real quota to a fraction of the intended 60 requests/5 minutes for whichever router came later in that list). `PATCH /whisps/:id/reveal` (called by the unauthenticated recipient) only ever returns `{id, revealRequested, revealAccepted}` — never the full whisp row — and requires `revealRequested` to already be true.
- **Scheduled sending**: a `whisp` with a future `scheduledAt` is created with `status: "scheduled"` instead of being delivered immediately (`lib/deliver.ts` holds the shared "actually send it" logic used by both the immediate path and the scheduler). `lib/scheduler.ts`'s `startScheduledWhispDispatcher()` polls every 60s for due whisps and delivers them via the same code path, then flips status to `delivered`. Ghost Boost ignores `scheduledAt` — it's always queued as `pending` since it isn't a direct-delivery method. Capped at `MAX_SCHEDULE_DAYS` (30, `lib/expiration.ts`) generally, and at the tighter `MAX_SCHEDULE_DAYS_WITH_UPLOAD` (5, `lib/uploads.ts`) when the whisp uses an uploaded video — otherwise a far-future schedule could outlive the video's own retention window. Both caps are validated before any Whisper Link quota or Ghost Boost credit is spent, and `scheduler.ts` re-checks an uploaded video's status again at actual dispatch time (not just at creation time) as a second line of defense — if it's no longer available, the whisp is marked `status: "failed"` and the sender is notified instead of a dead link going out.
- **Timestamp bookmarking + trimming**: `videoStartSeconds` on a whisp seeks the embedded YouTube/Vimeo player to that point on play (`VideoPlayer.tsx` — a `&start=` URL param for YouTube, `player.setCurrentTime()` for Vimeo). `videoEndSeconds` (must be after the start and at least 1 — `0` is rejected rather than treated as "unset", a post-launch fix: JS falsy-zero checks like `!data.videoEndSeconds` had let a `0` slip past validation and then get silently ignored during playback too, both `routes/whisps.ts`/`routes/whisperGroups.ts` and every enforcement site in `VideoPlayer.tsx` now check `!= null` instead; both trim fields are also capped at 86400 to keep an oversized value from ever reaching the `integer` DB column) trims the other end — playback is paused and treated as `watched_complete` once reached. This is enforced in JS (an interval poll + native `&end=` param for YouTube, a `timeupdate` listener for Vimeo, `onTimeUpdate` for native `<video>` uploads) rather than relying on a platform embed param alone, so it behaves consistently across all three playback paths. No-op for non-embeddable platforms, which just open the raw URL.
- **Pay-it-forward** (`src/lib/forwardVideo.ts`): after a recipient answers "yes, this was something I needed to hear," they can tap "Pass it forward" to carry that same video (including its trim, both start *and* end — the end was missing until a post-launch fix, silently dropping any end-trim on a forwarded clip) into their own Send Whisp composer, landing on `/send` after signing up or signing in — a one-shot handoff via `sessionStorage` (deliberately not `localStorage`: it's meant to survive exactly one sign-up hop, not persist indefinitely). Not offered for uploaded-video whisps, since the underlying bytes belong to the original sender.
- **Whisp-back**: the public reply endpoint (`POST /api/public/w/:token/reply`) accepts an optional video (scraped via the same `/api/video/meta` the sender's composer uses) alongside or instead of text — `replyText` is nullable at the API layer but stored as `""` in the DB (which keeps that column `NOT NULL`); a reply must have text, a video, or both.
- **Private Circles**: `circles`/`circle_members` tables gate a Circle Drop whisp's `circleId` to members-only — dropping into a circle you don't belong to is a 403, and a circle's private feed (`GET /api/circles/:id/feed`) is member-gated the same way. Circle Drop whisps with a `circleId` are deliberately excluded from the public `/api/public/circle` feed (`and(..., isNull(circleId), ...)` in `routes/circle.ts`) so a private drop never leaks into public discovery.
- **Push notifications**: `lib/push.ts`'s `notifyUser()` sends a Web Push message (via the `web-push` package and the `push_subscriptions` table) when a whisp is opened, watched to completion, or replied to, and `notifyUserPersisted`/`deliverInApp` fire the same live push alongside the in-app notification whenever a whisp/Text Whisp actually reaches a matched (known) recipient; dead subscriptions (404/410 from the push service) are pruned automatically. The frontend registers `public/sw.js` and subscribes through `src/lib/push.ts`, either proactively right after install (`EnableNotificationsPrompt.tsx`) or manually from the Settings page. `sw.js` also listens for `pushsubscriptionchange` — a browser can rotate/invalidate a subscription's endpoint on its own at any time — and re-subscribes with the stored VAPID key, re-registering the new endpoint with the backend, so a device doesn't silently stop receiving pushes forever after a rotation with nothing surfaced anywhere to explain why. Requires `VAPID_PUBLIC_KEY`/`VAPID_PRIVATE_KEY` to be set (see Run & Operate above) — without them this whole path is a no-op, so "installed app not getting notifications" on an otherwise-correct setup is worth checking those secrets first.
- **Admin panel** (`routes/admin.ts`, mounted at `/api/admin` behind `lib/adminAuth.ts`'s `requireAdmin`): full user management (search/filter, edit role/plan/boost credits, ban, delete with cascade), content moderation (list/inspect/delete any whisp across all users), and analytics. An admin can't ban, demote, or delete their own account through these endpoints (locking out the only admin would have no recovery path other than direct DB access). Regular `requireAuth` also checks `banned` on every authenticated request, so a banned user is rejected app-wide, not just from admin routes.
- **Video categorization** (`lib/categorize.ts`, `lib/transcript.ts`, `lib/categorizeWhisp.ts`): every whisp is tagged with up to 3 ranked categories (rank 1 = best fit) from a fixed 15-category taxonomy, run fire-and-forget right after creation. It's keyword-matching against the video title, boosted by a best-effort transcript scrape (YouTube captions only, via the watch page's caption-track JSON — no API key, no cost, but also no guarantee; other platforms categorize on title alone). Title matches count 3x a transcript match, so the transcript "confirms" rather than overrides the title's signal. Results land in `whisp_categories`, aggregated by `/api/admin/stats/categories` using a weighted score (rank 1 = 3pts, rank 2 = 2pts, rank 3 = 1pt) so the ranking reflects which categories most define what gets sent, not just raw tag volume.
- **Location capture**: `lib/geoip.ts` does a single best-effort IP → country/region/city lookup (via the keyless `ip-api.com` free tier) at signup, fire-and-forget, stored on the `users` row. This is about the registered *sender's* rough geography for admin analytics — it has nothing to do with, and doesn't weaken, the anonymity guarantee made to whisp *recipients* (who never see or affect this data). Private/loopback IPs (including the IPv4-mapped-IPv6 form Node reports for local dual-stack connections) are skipped rather than queried.
- **Smart analytics / opportunities** (`lib/insights.ts`): a handful of heuristic, data-driven checks (Whisper Link channel reply-rate comparison, free-plan users near their cap, category volume vs. watch-through rate, idle Ghost Boost credits, geographic concentration, peak send hour, scheduled-sending adoption) — each only fires once it has enough volume to say something meaningful. This is deliberately rule-based, not ML; every insight traces back to a real aggregate query.
- **Video privacy detection** (`routes/video.ts`): `/api/video/meta` now distinguishes "couldn't scrape a title" (still lets the sender proceed, since several allowlisted platforms have no oEmbed endpoint and scraping isn't 100% reliable even for public content) from a confirmed-blocked video — an oEmbed 401/403/404, or scraped content matching a known login-wall/"private video"/"video unavailable" pattern — which returns 422 with `code: "video_private"` or `"video_not_found"` and stops `SendWhisp.tsx` from advancing past step 1, so a sender can't unknowingly whisp a link the recipient won't be able to open.
- **Group Whisper** (`routes/whisperGroups.ts`, `lib/db/src/schema/whisper_groups.ts`): a sender-owned, reusable contact list (name + email/phone — not Blind Whisper accounts, added manually or via the Contact Picker's multi-select) that `POST /whisper-groups/:id/send` fans out to as one whisp row per member (each gets its own token/tracking/reply thread, functionally identical to a Whisper Link) tagged with a shared `groupSendId` so the sender's UI can roll them up into one logical send. Members missing the contact field the chosen channel needs are skipped and reported back, not silently dropped. Counts against the same free-plan Whisper Link monthly limit as any other Whisper Link (1 credit per member delivered). Recipient-facing copy (`lib/copy.ts`'s `groupHookLine`) is deliberately vague about who else is in the group — a headcount, never names — so no single member feels personally targeted even if one of them was the real reason it was sent; `PublicWhisp.groupSize` carries that count to the frontend. Video categorization runs once per send (not once per member) via `categorizeWhispsAsync`, since every member's whisp is the same underlying video.
- **Appreciation feedback**: the public whisp page asks "was this something you needed to hear?" (yes/no, answerable once and changeable afterwards — `POST /api/public/w/:token/appreciation`, stored as `appreciationResponse`/`appreciationRespondedAt` on the whisp). A fresh 'yes' answer (not a later change to one) notifies the sender by push and email; a 'no' is recorded the same way but doesn't notify, since there's no upside to a "they didn't like it" push. Shown to the sender in Whisp Detail and, per-member, in a Group Whisper send's detail view.
- **Whisper expiration + reminders** (`lib/expiration.ts`, `lib/reminderScheduler.ts`): `whisper_link`/`group_whisper` deliveries get an `expiresAt` 48 hours out, set at actual delivery time (not creation time, so a scheduled whisp's countdown starts when it's really sent) — `circle_drop`/`ghost_boost` never expire since there's no single recipient to create urgency for. The public page shows a live countdown and an offer to "remind me later" with preset times (`REMINDER_PRESETS` in `lib/expiration.ts` / the mirrored frontend copy in `src/lib/reminderPresets.ts` — keep both in sync); a chosen time is stored on `nextReminderAt` and re-delivers the same Whisper Link hook line via `lib/reminderScheduler.ts`'s 60s poller, capped at `MAX_REMINDERS` (2) total, with the final one's copy (`copy.ts`'s `reminderHookLine`) explicitly warning it's the last. `POST /api/public/w/:token/remind-me` rejects a requested time that would land at or after `expiresAt`, a whisp with no `expiresAt` at all, and any request once `reminderCount` hits the cap. Once `isExpired(expiresAt)` is true, `/track` silently no-ops (no status change, no sender notification) and `/reply`/`/appreciation` return 410 — the public page swaps the video/reply UI for an "this whisp has expired" state instead.
- **Video upload / Media Library** (`routes/media.ts`, `lib/objectStorage.ts`, `lib/uploads.ts`, `uploaded_videos` table): a sender can upload a short clip (capped at `MAX_UPLOAD_DURATION_SECONDS` = 2 minutes, `MAX_UPLOAD_VIDEO_BYTES` = 30MB — the size cap is the real server-enforced boundary; the duration is client-reported and trusted the same way pasted-URL video metadata already is elsewhere in this app) instead of pasting a URL. There's no ffmpeg (or any other video-processing binary) available in every environment this runs in, so there's **no server-side transcoding** — the thumbnail is captured entirely client-side (a hidden `<video>`/`<canvas>` frame grab, `src/lib/uploadMedia.ts`) and uploaded alongside the original video bytes. Storage is Replit Object Storage (`@replit/object-storage`, no API key needed — see Run & Operate above); every call degrades to a clear 503 rather than throwing if storage isn't configured, the same posture as Resend/Twilio/Stripe/VAPID elsewhere. A whisp created from an uploaded video stores a non-navigable `upload:<id>` marker in `videoUrl` (the column is `NOT NULL`) and sets `videoPlatform: 'upload'`, `uploadedVideoId`; actual playback/thumbnail always goes through a **token-scoped** endpoint (`/api/public/w/:token/media[/thumbnail]`) rather than a media-id-scoped one, so it resolves for whoever can see that specific whisp — the recipient, a Circle Drop browser, an admin — not just the uploader. The Media Library's own `/api/media/:id/...` endpoints stay owner-only, since browsing/reusing your own uploads before they're attached to any whisp has no token yet. Uploaded originals are phased out `UPLOAD_RETENTION_DAYS` (7) after upload — comfortably longer than a whisp's own 48h expiry + reminder window, so retention can never delete something not yet opened — with an email/push warning `UPLOAD_DELETION_WARNING_DAYS` (2) beforehand (`lib/mediaRetentionScheduler.ts`); the `uploaded_videos` row itself is never deleted, only flipped to `status: 'expired'`/`'deleted'`, so a whisp's reference always resolves to something (a 410, not a broken lookup). Upload hardening: the declared mimetype is checked against a small magic-byte signature (`looksLikeDeclaredVideoFormat`) so arbitrary non-video bytes can't be parked behind an unguessable link labeled as a video; a custom multer storage engine (`lib/fieldLimitedStorage.ts`) enforces the video/thumbnail size caps *per field* (multer's own `limits.fileSize` applies one ceiling across every field in a request, which would otherwise let a "thumbnail" field carry up to the video's much larger cap into memory before anything rejects it); `uploadLimiter`/`createWhispLimiter` key by the authenticated Clerk user, not IP, since these run after `requireAuth` and an IP-keyed limit is trivially bypassed by one account switching networks (or falsely throttles unrelated users sharing a NAT'd IP). A frontend `Thumbnail`/`VideoPlayer` fallback (an `onError` handler swapping to a placeholder) covers the case where client-side thumbnail capture failed and no thumbnail exists server-side.
- **AI takeaway** (`lib/aiTakeaway.ts`, `lib/takeawayScheduler.ts`): a short, therapist-toned "takeaway" of the video's real message (not a plot recap), generated for the **recipient** — Claude Haiku 4.5, transcript-based, so only ever available where a transcript exists (YouTube today; `aiTakeawayStatus` is `'unavailable'` everywhere else, `null` means "not attempted yet"). Triggered two ways: reactively, right after a `watched_complete` tracking event; proactively, via a 30-minute sweep that generates it anyway for `whisper_link`/`group_whisper` whisps nobody's watched `UNWATCHED_NUDGE_HOURS` (6) after delivery, so it's ready whenever they do open the link. Fire-and-forget and fully tolerant of failure (no transcript, a failed API call) — either way it lands on `'unavailable'`, never left hanging. The claim itself is a single atomic conditional `UPDATE ... WHERE aiTakeawayStatus IS NULL` (not a separate select-then-update), so the reactive and proactive triggers can't race and both spend an API call on the same whisp. The transcript is scraped from a video page the sender chose, so it's untrusted input from the model's perspective — the system prompt explicitly instructs Claude to treat it as content to interpret, never as commands, and to ignore anything inside it that reads like an instruction override (a caption track could otherwise be crafted to try to hijack the "AI therapist" framing). Shown on the public page as an animated, sentence-by-sentence staggered reveal (`PublicWhispPage.tsx`'s `TakeawayCard`, via `framer-motion`) right after the video card, and to the sender in Whisp Detail. Requires `ANTHROPIC_API_KEY`; without it, takeaways are just never generated — no other feature depends on this.
- **AI-assisted note writing** (`lib/noteSuggestions.ts`, `POST /whisps/note-suggestions`): a "Help me find the words" button in the composer's anonymous-note step (`SendWhisp.tsx` step 3) sends the video's title + chosen mood tag (no transcript — the whisp doesn't exist yet at compose time, so there's nothing to fetch, and skipping it keeps the call fast and cheap) to Claude Haiku 4.5 and gets back 3 short note options the sender can tap to fill the textarea, tweak, or regenerate. Same cheap/fast model tier as the AI takeaway feature, plus a tight `max_tokens` cap and no extended thinking, since a one-sentence suggestion doesn't need either — and `noteSuggestionLimiter` (`lib/rateLimit.ts`, per-user like the other authenticated limiters) bounds how many times one account can call it. Unlike the takeaway feature this is a synchronous request from the composer, not fire-and-forget, but follows the same tolerant-of-failure posture: no `ANTHROPIC_API_KEY`, a failed model call, or an empty/malformed response all just return an empty suggestion list rather than erroring the request. The video title is scraped third-party metadata (the video uploader's own `og:title`/oEmbed data, not the sender's own input) — same untrusted-input posture as the AI takeaway's transcript, so the system prompt explicitly instructs Claude to treat it as content to interpret, never as instructions (a post-launch fix; an earlier version of this comment incorrectly claimed nothing untrusted reached this prompt).
- **Suggestions Library** (`suggested_videos` table, `lib/videoMeta.ts`, `lib/suggestionSummary.ts`, `lib/suggestionAgent.ts` + `lib/suggestionAgentScheduler.ts`, `routes/admin.ts`'s suggestions section, `routes/suggestions.ts`): an admin-curated (and AI-discovered) gallery of third-party video links, separate from a user's own uploads/pastes, meant to be browsed and "whispered" to someone in your circle. An admin adds a video link (YouTube/TikTok/Instagram/Facebook/Vimeo/X), tags it with 1-5 categories from the same 15-category taxonomy whisps use (Postgres array column, since this is admin-curated multi-membership, not the ranked rank/score pairs `whisp_categories` uses), and can mark it featured; `lib/suggestionSummary.ts` fires the same atomic-claim/Claude-Haiku-4.5 pattern as the AI takeaway feature to generate a one-sentence "why this is worth sharing" blurb from the scraped title. Every video URL — admin-entered or agent-discovered — is resolved through `resolveVideoMeta()` in the newly-extracted `lib/videoMeta.ts` (pulled out of `routes/video.ts`, which is now a thin wrapper around it), so the hostname allowlist/SSRF guard and private-content detection are never duplicated or weakened across entry points. The **AI discovery agent** (`lib/suggestionAgent.ts`, run daily by `startSuggestionAgentScheduler()`) uses Claude's server-side `web_search_20250305` tool, biased toward the same allowlisted domains via `allowed_domains`, to find a small number of real videos per category (`CATEGORIES_PER_RUN` = 3, rotating through the taxonomy by day; `VIDEOS_PER_CATEGORY` = 2 — deliberately small to keep API/token cost predictable) — every URL it returns still goes through the exact same `resolveVideoMeta()` allowlist check as any other entry point (an LLM-produced URL is never trusted past that gate), and survivors are deduped against the existing library and inserted as `status: "pending"` / `source: "ai_agent"`, invisible to users until an admin approves them from the admin Suggestions page (never auto-published — a deliberate content-safety gate the user chose over faster auto-publish). Search-result content is treated the same as any other untrusted scraped text: the system prompt explicitly instructs Claude to ignore anything inside a search result that reads like an instruction override. The "Whisper this" action on a suggestion reuses `lib/forwardVideo.ts`'s existing one-shot `sessionStorage` handoff unmodified (same shape whisps already use for pasted URLs, minus trim points) to carry the video into Send Whisp.
- **Suggestion agent run status** (`suggestion_agent_status` table, a singleton row keyed `id: "singleton"`): since the daily scheduler doesn't run immediately on server start (same as every other scheduler in this app — the first fire is a full interval away), `POST /api/admin/suggestions/run-agent` lets an admin trigger a sweep on demand instead of waiting, and the admin Suggestions page shows a status banner (never-run / healthy / failed) so a stuck agent doesn't fail silently for a day before anyone notices. Every category's `web_search` call failing *together* in one run (as opposed to one flaky category among several that succeeded) is treated as a systemic failure worth recording — `lib/suggestionAgent.ts`'s `looksLikeLowCreditError()` does a deliberately loose substring match on the error message (Anthropic surfaces a depleted credit balance as plain message text, not a distinct error code) to tell "stopped because the Anthropic account needs more credit" apart from a generic/transient failure, since only the former needs a human to actually do something about it. `consecutiveFailures` resets to 0 the moment any run succeeds again.

## Product

- **Send Whisp**: composer — choose a video source (paste a URL, checked for private/restricted/deleted before you can proceed; upload a clip from your device; or reuse one from your Media Library) → mood tag (+ optional "trim the clip" start/end mm:ss) → anonymous note (with an AI "Help me find the words" suggestion button) → delivery method (+ channel picker for Whisper Link/Group Whisper: email/SMS/WhatsApp, a circle picker for Circle Drop: public feed vs. a private circle, or a saved-group picker for Group Whisper) → optional "Schedule for later" toggle + datetime → recipient (Whisper Link: type one, with an optional "Choose from Contacts" button where the browser supports it) → confirm, which shows the same rich video preview card (thumbnail, platform icon, title — `PlatformIcon`, shared with the Suggestions Library pages) used earlier in the flow, not just a bare thumbnail. Arriving via a "Pass it forward" hop pre-fills the video/trim and jumps straight to step 2.
- **Dashboard**: stat cards (sent, open rate, watched, replies) + recent whisps + boost credit counter
- **My Whisps**: filterable list (now including a `scheduled` status filter) with status badges, thumbnails, mood tags
- **Whisp Detail**: delivery timeline (sent/delivered/opened/clicked/watched/replied) driven by real tracking events, anonymous reply thread (text and/or a "whisp-back" video), follow-up send, reveal flow, scheduled-send date shown when applicable. A Ghost Boost campaign instead shows aggregate match stats (matched/opened/watched/replied/appreciated counts) in place of the single-recipient timeline/follow-up/reveal sections, which don't apply to a fan-out with no one known recipient.
- **Replies Inbox**: all whisps that received an anonymous reply
- **Circle**: public community discovery feed of Circle Drop whisps — no recipient, organic browsing
- **My Circles**: invite-only private circles — create one, join with an invite code, and view a circle's own private feed at `/circles/:id`; Send Whisp's Circle Drop step can target a specific circle instead of the public feed
- **Credits & Plan**: subscription tiers (Spark/Ember), Ghost Boost credit packs — real Stripe Checkout
- **Settings**: profile edit, account info, push notification opt-in/out, privacy policy
- **Public `/w/:token`**: recipient landing page — no account required to view or reply. Watch video (optionally starting/ending at the sender's chosen trim points, always embedded in the same Blind Whisper template regardless of platform — pasted URLs, uploads, and everything else all render through one `VideoPlayer`), see mood/note, a live "expires in..." countdown with a "remind me later" preset picker for Whisper Link/Group Whisper sends, an animated AI takeaway once it's ready, reply anonymously (quick-reply chips, free text, and/or whisp a video back), answer the appreciation prompt (a "yes" offers to "Pass it forward" into the recipient's own Send Whisp composer), accept/decline reveal, and two invite CTAs — "Become a Whisperer" to `/sign-up`, and "Want more, matched to you?" to `/subscribe` (the matching-queue opt-in); a confetti burst fires from the tap point right before playback starts (`VideoPlayer.tsx`). Once expired, the video/reply/appreciation UI is replaced with an expired-state message.
- **Subscribe / matching queue** (`/subscribe`, `/verify-subscription`, `/unsubscribe`): a public, unauthenticated opt-in flow for anyone who wants anonymous whisps matched to topics they pick, without a Blind Whisper account — see the matching-queue architecture bullet above for how sends actually get fanned out.
- **Admin panel** (`/admin`, visible in the nav only to accounts with the `admin` role — see `ADMIN_EMAILS` above): an Overview dashboard (user/whisp counts, 7-day active users, 30-day signup/whisp trend charts, computed "smart analytics" opportunity cards); a Users page (search/filter by plan/role/banned, ban/unban, edit role/plan/credits, delete with full cascade) with a per-user detail view (activity, credit transaction history); a Content page listing every whisp across all users (search/filter by status/delivery method/category, delete for moderation) with a full detail view (sender, transcript, ranked categories, tracking timeline, replies); and an Analytics page (most-sent video categories ranked by weighted score, delivery method + Whisper Link channel breakdown, users by country/city).
- **Whisper Groups** (`/whisper-groups`): create/manage saved contact groups (add members via the Contact Picker's multi-select or manual entry), send the same anonymous whisp to every deliverable member at once from Send Whisp's "Group Whisper" delivery option (reuses the email/SMS/WhatsApp channel picker, mood/note/timestamp/scheduling all work the same as a regular Whisper Link), and a "Sent Batches" tab showing past group sends aggregated with a per-member status/reply breakdown at `/whisper-groups/sends/:groupSendId`.
- **Media Library** (`/media-library`): a sender's uploaded video clips, reusable across whisps — thumbnail, size, per-clip usage count, a countdown to automatic phase-out, and manual delete.
- **Suggestions Library** (`/suggestions`): a gallery of admin-curated (and admin-approved AI-discovered) videos, filterable by category/featured, each with a scraped thumbnail/title and an AI-generated one-line summary — "Whisper this" carries a suggestion into Send Whisp the same way pay-it-forward does. Surfaced via a nav link and a Dashboard card (spotlighting a random featured video when one exists). Admins manage the library from `/admin/suggestions` — add videos manually, approve/archive/feature/delete, and review AI-agent-discovered candidates awaiting a look.
- Mobile: native-style bottom tab bar with a raised Send action, safe-area-aware header/footer padding throughout, no browser-native `confirm()`/`alert()` dialogs (destructive actions use the in-app `AlertDialog`), tap-highlight and overscroll bounce disabled globally. The admin panel is a simpler top-nav layout (desktop-first, since app-owner usage skews desktop) but still renders usably on mobile.

## Gotchas

- Always import `zod` not `zod/v4` in server route files
- CSS: Google Fonts `@import url(...)` must be the FIRST line in `index.css` (before tailwindcss import)
- `@clerk/themes` is a separate devDependency in `@workspace/blindwhisper` — not bundled with `@clerk/react`
- API server runs on port 8080, proxied at `/api` via artifact.toml
- Run `pnpm --filter @workspace/api-spec run codegen` after any change to `openapi.yaml`
