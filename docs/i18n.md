# Internationalization

## Languages

`SUPPORTED_LANGUAGES` (8, all fully translated): **en** English, **fr** French,
**ar** Arabic, **de** German, **es** Spanish, **zh** Chinese, **sw** Swahili,
**ko** Korean.

Do not add a language as an empty stub — earlier stubs (pt/ja/hi/ru/id/bn) were
removed because a listed-but-untranslated language is worse than not listing it.
Adding a language means translating **all namespaces** and validating key parity,
plural forms, and interpolation placeholders before it ships.

## Structure

- `artifacts/blindwhisper/src/i18n/locales/<lng>/<namespace>.json`
- Namespaces (11): sharedA, sharedB, whisps, textWhisps, circle, debate, account,
  media, publicPages, and the rest per feature area — mirror `en/` exactly.
- `users.preferredLanguage` stores the choice; the language switcher lives in
  settings/onboarding. Backend notification/email templates respect it where
  implemented.

## Conventions

- **Protected product terms stay English in every language:** Blind Whisper,
  Whisp(s), Whisper Link(s), Whisperer(s), Blind Circle(s), Debate Now,
  Town Crier, Circle Scout, Ghost Boost, Whisper Box.
- The **admin panel is English-only**; legal pages (privacy, terms, sms-terms,
  community guidelines) are English-only.
- Interpolation placeholders (`{{name}}`) and plural suffixes (`_one`/`_other`,
  plus language-specific plural forms — Arabic has six) must match `en` exactly.

## RTL

Arabic switches the document direction: the i18n init sets
`document.documentElement.dir = "rtl"` for RTL languages and back to `ltr`
otherwise. Test layout changes in Arabic before shipping UI work.

## Adding strings

1. Add the key to the `en` namespace file.
2. Add translations to the other 7 locales (translate meaning, not word-for-word;
   keep protected terms English).
3. Use via `useTranslation("<namespace>")`. Never hardcode user-facing strings in
   components outside the admin panel.
